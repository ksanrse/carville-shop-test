# CARVILLE SHOP — разводящая страница брендов

Тестовое задание: страница брендов интернет-магазина CARVILLE SHOP по макету Figma (десктоп + мобильная версия, первый этап — только собственные бренды).

**Чистое время выполнения: 1 ч 57 мин**

## Запуск

Требования: Node.js 24+, pnpm 12+.

```bash
pnpm install      # установить зависимости
pnpm dev          # dev-сервер на http://localhost:3000
pnpm build        # production-сборка
pnpm preview      # запустить production-сборку локально
pnpm lint         # oxlint + проверка форматирования oxfmt
pnpm lint:fix     # автоисправление
pnpm typecheck    # проверка типов (vue-tsc)
```

Деплой на Vercel: `npm i -g vercel && vercel` (или импорт репозитория в Vercel). Nuxt определяется автоматически, настройки не нужны.

Маршруты:

- `/` → временный редирект (307) на `/brands`, пока нет главной;
- `/brands` — разводящая брендов;
- `/brands/:slug` — заглушка страницы бренда (каталог — следующий этап);
- `/api/brands`, `/api/brands/:slug` — данные.

## Тесты и защита от «ИИ-косяков»

Тестов мало намеренно: каждый проверяет то, что реально ломается.

| Слой                                            | Что                                                                                                                                              | Где                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- |
| Unit / компоненты (Vitest + `@nuxt/test-utils`) | контракт данных (уникальные slug, логотипы существуют), карточка-ссылка и доступность, активный пункт меню, крошки, поиск без JS, форма подписки | `test/unit`               |
| E2E (Playwright, по production-сборке)          | витрина без ошибок в консоли и битых картинок, ховер-состояние, переход карточка → бренд → назад, мобильная версия без горизонтального скролла   | `test/e2e/brands.spec.ts` |
| SEO (Playwright)                                | title/canonical/lang, schema.org (`CollectionPage`, `ItemList`, `BreadcrumbList`), 307 с `/`, 404, `robots.txt`, `sitemap.xml`, `llms.txt`       | `test/e2e/seo.spec.ts`    |
| Guard + baseline (`scripts/guard-tests.mjs`)    | защита от молчаливого удаления/ослабления тестов при работе с ИИ-агентами                                                                        | `test/baseline.json`      |

Хуки ([Lefthook](https://lefthook.dev), ставятся сами при `pnpm install`):

- **pre-commit** — oxlint (`--deny-warnings`) и oxfmt по изменённым файлам, запрет `.only` / `.skip` / `debugger` и похожих на секреты строк.
- **pre-push** — `pnpm verify`: lint → типы → unit с покрытием → сборка → e2e → guard.
- **CI** (`.github/workflows/ci.yml`) — тот же `pnpm verify`; `--no-verify` его не обходит.

**Защита от удаления тестов** (история с OpenClaw: тесты тихо удаляли так, что покрытие не падало). `scripts/guard-tests.mjs` сверяет результаты прогона с `test/baseline.json`: число тестов (unit и e2e) и покрытие (lines / functions / statements / branches) не могут уменьшиться. База сравнивается ещё и с `origin/main`, так что понизить `baseline.json` в том же пуше — тоже ошибка. Плюс пороги покрытия в `vitest.config.ts`, `allowOnly: false` и правила oxlint `vitest/no-focused-tests` и `no-disabled-tests` в тестах. Осознанное изменение — `node scripts/guard-tests.mjs --update` отдельным коммитом с объяснением. Для полной защиты в GitHub включите branch protection: обязательный CI и review.

```bash
pnpm test            # unit
pnpm test:coverage   # unit + покрытие
pnpm test:e2e        # e2e (нужен pnpm build)
pnpm verify          # всё сразу, как перед пушем
```

## SEO и AI-агенты

- `robots.txt` (`@nuxtjs/seo`): ссылка на sitemap и `Content-Signal: search=yes, ai-input=yes, ai-train=no` — индексация и ответы ассистентов разрешены, обучение моделей на контенте — нет.
- `sitemap.xml`: страницы брендов берутся из того же источника данных, что и сами страницы (`/api/__sitemap__/brands`).
- `llms.txt` — краткая карта сайта для LLM-агентов (`server/routes/llms.txt.ts`), в `<head>` есть `rel="alternate"` на него.
- schema.org (`CollectionPage`, `ItemList`, `BreadcrumbList`), canonical, `lang="ru"`, `theme-color`, SVG-фавикон.
- Ссылки на ещё не перенесённые разделы — обычные `<a>` (полная загрузка с Bitrix), а не клиентский роутинг.

## Почему так

- **Vue/Nuxt.** Фреймворк «из коробки»: роутинг, SSR, SEO, серверные роуты — без сборки своего зоопарка. Vue-разработчиков проще найти, чем Svelte/Solid, а ИИ-инструменты пишут на нём уверенно. Разница в перфе с Solid/Svelte на витрине магазина некритична: страницы рендерятся на сервере и кэшируются.
- **Почему Vue проще для ухода с Bitrix:**
  - Vue уже есть внутри Bitrix (расширение `ui.vue3` / BitrixVue), и на нём написан современный интерфейс самого Bitrix. Команде, которая поддерживает текущий сайт, не нужно учить новый фреймворк.
  - Шаблоны Vue — это HTML с директивами, близкие к PHP-шаблонам компонентов Bitrix. Вёрстку из `template.php` можно перенести почти как есть, без переписывания в JSX.
  - Vue можно подключать островками прямо в страницы Bitrix (`createApp` на отдельный блок, без SSR и сборки всего сайта). Значит, одни и те же компоненты (карточка, корзина, поиск) сначала живут внутри Bitrix, а потом без изменений переезжают в Nuxt. Миграция идёт по компонентам, а не одним большим переписыванием.
- **Поэтапная миграция с Bitrix (strangler fig).** Страницы переезжают по одной, Bitrix работает рядом. Роутинг на уровне прокси/домена отдаёт новые разделы из Nuxt, остальное — из Bitrix. Поэтому ссылки в шапке и футере ведут на ещё не перенесённые разделы — это нормально.
- **Слой данных.** Страницы ходят только в `/api/*`. Сейчас там моки (`server/utils/brands.ts`); дальше — прослойка над Bitrix, затем свой бэкенд. Фронт при этом не меняется.
- **SSR + ISR.** Полноценный HTML для поисковиков, schema.org (`CollectionPage`, `ItemList`, `BreadcrumbList`), страница отдаётся из кэша Vercel.

## Анимации

- Каскадное появление карточек при загрузке.
- Ховер карточки (по аннотации в макете): появляется тень (`drop-shadow`), проявляется фирменный градиент плитки, кнопка становится оранжевой, а стрелка поворачивается на 45°. Форма с вырезом под кнопку — `border-image` из SVG.
- На тач-устройствах то же состояние по `:active` / `:focus-visible`.
- Морфинг логотипа из карточки на страницу бренда (View Transitions API).
- Нажатие кнопок (`scale`), иконки нижнего меню.
- Всё отключается при `prefers-reduced-motion`.

## Как использовался ИИ

Код почти целиком написан ИИ-агентами. Моя роль — постановка задач, архитектурные решения и контроль качества. Главный принцип: агенту не верят на слово, каждое утверждение проверяется автоматически или по исходникам.

1. **Макет → код.** Claude Code читал макет через Figma MCP (структура, токены, ассеты). Результат сверялся скриншотами Playwright с макетом на 1440 / 900 / 390 px.
2. **Автоматические рамки до первой строки кода.** `pnpm verify` (lint → типы → unit с покрытием → сборка → e2e по production-сборке), хуки и CI. Агент считает задачу выполненной, только когда `verify` зелёный.
3. **Guard от «читерства» агента.** Типичный сбой ИИ — сделать тесты зелёными, удалив или ослабив их. `guard-tests` с baseline это ловит (см. «Тесты»).
4. **Перекрёстное ревью двумя агентами.** Claude Code и Devin (SWE-2 max) независимо проверили проект. Находки сведены и проверены вручную: одна «критичная» оказалась ложной, это подтвердилось по исходникам Nuxt. Исправления делал Devin по сводному списку, а Claude Code проверил diff и прогнал `verify`.
5. **Где пришлось вмешиваться.** После исправлений упало покрытие ветвлений: v8 считает ветки у автоимпортов, вызванных прямо в шаблоне. Агент пытался добавлять тесты. Реальная причина нашлась в lcov, лечится переносом вызова в `computed`.

Зачем столько проверок для одной страницы: каждая закрывает конкретный риск. E2E по production-сборке ловят то, что не видно в dev (ISR, редиректы, 404). SEO-тесты нужны, чтобы при переезде с Bitrix не потерять позиции в поиске. 100% покрытие — это не самоцель, а сигнал для guard: любой удалённый тест сразу заметен.

## Открытые вопросы к дизайну

- Градиент при ховере нарисован только для STARTVOLT; для остальных брендов временно нейтральный графитовый.
- Название в макете пишется по-разному: «CARVILLESHOP» и «CARVILLE SHOP».
- Тень карточки в Figma со spread; `drop-shadow` его не поддерживает, тень подобрана близко.
- Планшетная ширина в макете не нарисована — сетка адаптивная (auto-fill).
- Контраст `grey-m`/`grey-l` на светлом фоне ниже WCAG AA — цвета из макета.
- `site.url` в `nuxt.config.ts` — заглушка до появления боевого домена.
